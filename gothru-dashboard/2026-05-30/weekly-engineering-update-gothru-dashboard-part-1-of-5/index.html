Issue #1277: Migrate API Preview Tour to ADR Architecture

Author: anurdin01 | Updated: 2026-05-30T01:10:36Z

Task Description

Empty

Demo by Developer

This API has been migrated to the ADR architecture. For more details, please see : https://github.com/GoThruMedia/GoThru-API-New/blob/main/docs/v2/tours/preview-tour.md

Document docs/v2/tours/preview-tour.md

preview-tour.md

Path: docs/v2/tours/preview-tour.md

Tours — Preview Tour

GET /tours/preview/{mid}

Auth: middleware('auth')

Flow:

  1. Request enters → PreviewTourController@handle builds PreviewTourDto from user_id (auth) and mid (route param).
  2. Controller delegates to PreviewTourAction::execute(PreviewTourDto).
  3. Action runs business logic:
    • Check if user_id is a super-user (via SUPER_USER env).
    • Check if user owns the moderation record via ToursRepository::checkModerationOwnership() — if not owner and not super-user, throw TOURS.MODERATION_NOT_OWNER.
    • If super-user, fetch the actual owner's user_id via ToursRepository::getModerationInfo() and substitute it.
    • Resolve short URL via PreviewClass::checkShortUrl(), then generate the preview link via PreviewClass::generatePreviewLink().
    • Returns preview URL as a string: https://gothru.co/P{shortUrl}.
  4. Controller receives URL → checks ec request header to decide response shape:
    • ec is null / "" / "true" → ResponseEnvelopeHelper::encryptResult() (encrypted)
    • any other value → ResponseEnvelopeHelper::responseMessages() (plain)
    • ToursDomainException → ToursExceptionHttpMapper::toStatusCode() → responseMessages()
    • \Throwable → statusCodeFromThrowable() → responseMessages()

DTO (app/DTOs/Tours/PreviewTourDto.php):

FieldTypeSourceNotes
user_idint$request->user_idinjected by auth middleware
midintroute param {mid}moderation ID

Response (200) — encrypted (default, ec header null / "" / "true"):

{
  "statusCode": 200,
  "data": {
    "messages": "Preview link generated",
    "cry": "<encrypted payload>",
    "ls": "...",
    "e4": "..."
  }
}

Response (200) — plain (ec header = any other value):

{
  "statusCode": 200,
  "data": {
    "messages": "Preview link generated",
    "url": "https://gothru.co/P<shortUrl>"
  }
}

Payload url = https://gothru.co/P{shortUrl}. Encryption toggled by ec request header at Controller transport edge.

Errors:

domainCodeHTTPCondition
TOURS.MODERATION_NOT_OWNER409user_id not owner of mid (non-superuser)
(fallback \Throwable)dynamicResponseEnvelopeHelper::statusCodeFromThrowable()

Usage:

# Encrypted response (default)
curl -X GET https://api.gothru.co/tours/preview/{mid} \
  -H "Authorization: Bearer {token}"

# Plain response
curl -X GET https://api.gothru.co/tours/preview/{mid} \
  -H "Authorization: Bearer {token}" \
  -H "ec: false"

Notes:

  • Super-user (SUPER_USER env) bypasses ownership check — uses tour owner's user_id for link generation.
  • Preview generation orchestration lives in PreviewService; preview table queries isolated in PreviewRepository.
  • Compliance: 100% ADR.
